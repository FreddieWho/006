# 科研方案 v5.2a

**Multi-cancer immunotherapy-specific causal GRN for PD-1+X / X+X combination ranking and target recommendation**

> 本版在 v5.2 基础上做的变化：
>
> 1. 把“真正的任务”写实——不是泛泛机制发现，而是**在多癌种免疫治疗场景下对PD-1+X、X+X组合做相对效能排序并给出靶点/药物推荐**；
> 2. 明确“算法达标后进入动物验证”，只写目标不展开模型、剂量和时间表；
> 3. 指定主叙事优先来自**共享层模块**，癌种特异做补充；
> 4. 加入一个可做的“弱外部锚点”思路，保证能和患者层面挂上钩；
> 5. 保留分层推荐（Tier A/B/C）、免疫核心基因集、共享+特异双层GRN、预注册顺序。
>    目的是：用这一份就能在任何对话里完整重启当前研究，而且方向对准 NC / NM / Cancer Cell 级别，而不是下降到 NCmm 一档。

---

## 1. 科研目标与定位

### 1.1 总体目标

构建一个**跨癌种、面向免疫治疗组合决策**的因果基因调控网络（causal GRN），在单细胞分辨率下：

1. 学到**跨癌种共享的免疫反应/免疫抑制机制模块**；
2. 同时保留**肝、肺、黑色素瘤等癌种/组织特异的免疫约束模块**；
3. 在此基础上，对候选的 **PD-1+X** 或 **X+X** 组合做**相对效能排序（ranking）**，并给出对应的**可干预靶点/药物推荐**；
4. 算法性能达标后，进入**最小限度体外验证 + 目标化的体内验证**，完成能投 NM/NC/CC 所需的生物学闭环。

一句话描述任务：

> “我们要做的是一个 multi-cancer、immunotherapy-specific 的因果网络，用来比较不同免疫联合组合的有效性，并从中挑出能转化的靶点。”

### 1.2 期刊定位

* 主定位：**Nature Cancer / Cancer Cell / Nature Medicine** 这一IF>20区间；
* 算法阶段必须产出可讲的一号机制 + 至少一个外部/患者层面的锚点；
* 生物学阶段至少要有1条能进动物的明确目标，写进方案但不展开。

---

## 2. 生物学假设

1. **双层免疫机制假设**：免疫检查点治疗相关的核心过程（抗原呈递、IFN响应、CD8浸润障碍）在不同癌种之间存在可共享的调控结构，但每个癌种又叠加了器官/组织特异的免疫约束（如肝脏耐受）。
2. **因果可提升假设**：将公开的扰动类数据（perturb-seq、Xatlas-orion）作为软先验嵌入GRN，可提升边方向的可信度，使得后续对“干预谁能改善响应”这一问题的推断更可靠。
3. **组合可映射假设**：共享/特异模块中的高中心性、扰动敏感且可药化的基因，会对应到现实中已有或在研的免疫联合药物，因此可以形成分层推荐（Tier A/B/C）。
4. **阶段性验证假设**：在算法性能、模块显著性和体外验证达标之前不推进动物实验；一旦达标，就按方案中预定义的动物实验目标进入验证。

---

## 3. 数据前提与免疫核心基因集

* **数据构成**：多癌种免疫治疗患者单细胞转录组（肝癌、肺癌、黑色素瘤、头颈癌等），其中一部分具有治疗前后配对与疗效（如RECIST）信息，可用作弱监督。
* **先验资源**：LINCS1000 药物表达谱、perturb-seq、Xatlas-orion 等大规模扰动数据，用于因果软约束与药物映射。
* **免疫核心基因集（重要新增）**：
为在跨癌种框架下获得具有可解释性且客观的免疫相关特征空间，我们首先在TCGA多癌种转录组数据中建立免疫活性基因池（IAGP）。
IAGP的构建遵循“表达活性而非基因集来源”的原则，综合评估每个基因与多维免疫功能状态的关联，包括 IFN-γ/IFN-α 响应、细胞毒活性（CYT）、MHC-I/MHC-II 抗原呈递、炎症趋化、TGF-β 抑制通路、WNT/β-catenin 排斥轴及低氧/血管生成等指标（参考 Thorsson et al., Immunity 2018; Mariathasan et al., Nature 2018）。
在每个癌种中，我们计算基因表达与上述各维度免疫活性分数的相关性，并控制肿瘤纯度、细胞增殖和批次效应等混杂因素。随后进行跨癌种元分析，仅保留在≥3个癌种中显著且方向一致（meta-FDR < 0.05）的基因，形成IAGP核心列表。
为避免组织特异信号污染，我们利用GTEx及Human Protein Atlas数据对高组织特异或器官主导的基因进行标签标注（而非剔除），供后续共享-特异层分流使用。
最终的IAGP（v1.0）作为跨癌种共享层的特征空间输入，其模块化学习与GSEA仅用于语义命名，不参与筛选或决策。

## 4. 技术路线（七层）  

### Layer 0：多癌种整合与加权

* 用 scVI / Harmony 消除批次效应；
* 统计“中心×癌种”样本量，构造权重 (w_{center,cancer})，在训练损失中乘权，防止单一癌种（常是HCC）主导图结构。

### Layer 1：TME与细胞状态表征

* 标准单细胞流程：聚类、细胞类型注释、免疫/肿瘤状态标记、治疗前后状态对比；
* 输出能用于“应答 vs 不应答”和“前 vs 后”这两类弱监督信号，为后面做组合排序提供真实梯度。

### Layer 2：共享 + 特异的跨癌种因果GRN（核心）

* 总损失：
  [
  L = \sum_c L_{\text{pred}}^{(c)}

  * \lambda_{\text{share}} L_{\text{shared}}
  * \lambda_{\text{tissue}} L_{\text{tissue-specific}}
  * \lambda_{\text{causal}} L_{\text{GRN-prior}}
  * L_{\text{reg}}
    ]

  - (L_{\text{shared}})：在免疫核心基因集上学一张跨癌种共享图 → 告诉我们“免疫治疗里都在动的那部分”；
  - (L_{\text{tissue-specific}})：允许肝/肺/黑色素瘤保留残差 → 把器官性免疫约束当成“癌种特异模块”报告；
  - (L_{\text{GRN-prior}})：用 perturb-seq / Xatlas 的方向信息做软约束（建议 (\lambda_{\text{causal}} \approx 0.2–0.4)）；
  - 超参用**贝叶斯优化**同时找 (\lambda_{\text{share}}, \lambda_{\text{tissue}}, \lambda_{\text{causal}})，避免网格搜索的选择性偏倚。
* 生物学说明：对确有意义的器官性免疫耐受（如肝）不强塞进共享层，而是在特异层中单独呈现。

### Layer 3：预先计划的机制模块发现

* 主分析：分辨率=1.0，Louvain/Leiden，模块大小 15–50；
* 成功标准：≥50% 模块在标准GSEA下 FDR<0.05；
* 次/稳健性分析：分辨率 0.5/1.5 + weighted GSEA，仅作支持不做主结论；
* 若主分析 <30% 模块显著 → 启动差异通路分析或网络社区富集（降级路径写在方法，不写在目标段）；
* 预注册中写清楚这一顺序，防止“事后挑结果”。

### Layer 4：多层级解释 + 结构一致性验证

* 解释顺序：标准GSEA → SHAP加权GSEA → 应答/不应答差异通路；
* 结构一致性验证（轻量）：

  * 与 ENCODE/GTRD 的 TF→target 做重叠度；
  * 与 STRING 实验支持边做 top-k 一致性；
  * 结果进补充，用来证明网络结构不是随机图。
* 在这一层就可以挑出**“一号共享模块”**——那个在多个癌种都显著且与免疫治疗响应最相关的模块，后面主图都围绕它讲。

### Layer 5：瓶颈靶点识别与组合排序入口

* 综合分数：
  [
  \text{Score}(g) = 0.4 \times \text{Centrality}
  + 0.3 \times \text{SHAP}
  + 0.2 \times \text{PerturbEffect}
  + 0.1 \times \text{Druggability}
  ]
* 从“一号共享模块”里先挑 Top-1/Top-2，说明这是后面要进实验的；
* **组合排序的信号来源**写清楚：

  * 有治疗前后配对 → 看模块/靶点的方向性变化；
  * 有应答/不应答 → 看模块score的分组差异；
  * 用这些弱监督去比较“PD-1+X” vs “PD-1+Y”哪条链在网络里能修得更彻底。
    这样就能说：“我们不是凭空排组合的，我们是用真实病人反应信号做了校准的。”

### Layer 6：分层的靶点/药物/组合推荐（技术实现外移）

* **Tier A（优先报道）**：靶点可映射到免疫联合相关的FDA已批药或正在II/III期、且机制和我们发现的模块一致 → 这部分可以写进主文；
* **Tier B（假说级）**：只有LINCS/研究级化合物支持表达反向/机制契合 → 标注“需体外验证”；
* **Tier C（机制级）**：无药可映射 → 只报机制，不报组合；
* 在科研方案中说明：**具体的打分细则和实现逻辑在技术文档中给出，此处不展开**，以保持篇幅和重点。

## 5. 验证与分阶段实验

### 5.1 计算/算法层面的达标条件（必须先过）

1. LOCO（留一癌种）与留一中心验证均达到预设AUC，并报95% CI；样本 <30 的癌种只做描述性；
2. 主分析达到 ≥50% 模块显著或已按预注册进入降级路径；
3. 消融实验显示：去掉 (\lambda_{\text{share}}) 或 (\lambda_{\text{tissue}}) 性能下降，证明“双层结构有用”。

### 5.2 体外功能验证（投稿包的一部分）

> “在提交前将对综合评分最高、且位于一号共享模块内的1–3个候选靶点进行最小限度功能验证（如敲低/抑制后检测免疫相关readout或与免疫协同的分泌/信号变化），以实例化证明平台的发现能力。”

这样写进去，审稿人就不会说“你全算的”。

### 5.3 体内实验的目标性描述（只写目标，不写细节）

> “在算法性能与体外验证达标后，将推进以一号共享模块中排名最高的候选靶点/组合为对象的体内验证，目标是证明：
>
> 1. 在免疫治疗背景下干预该靶点能部分解除网络推断出的关键免疫障碍；
> 2. 与PD-1/PD-L1联用能获得方向一致的疗效增强；
> 3. 若靶点来自共享层，则在代表性癌种模型中能观察到相同趋势。
>    体内实验的具体模型、时间表和剂量在本阶段不展开，随算法结果与资源情况统一规划。”

这句话既写进了NM需要的那一环，也保留了你说的“现在不展开”的要求。

### 5.4 弱外部锚点

> “为证明模块在患者层面具有可迁移性，将在可获得的免疫治疗bulk或空间转录组队列上计算一号共享模块score，评估其对应答/不应答的区分能力（即使为中等AUC），以此作为跨平台的临床相关性锚点。”

这是一件当下就能做的事，又能让稿子看起来是“和病人相关的”。

## 6. 主叙事与写作指引

1. **主线固定在共享层发现的免疫治疗相关模块上**，这是最能体现“multi-cancer immunotherapy-specific”价值的部分；
2. **二线写癌种特异**：说这套方法还能拆出肝/肺/黑色素瘤特有的免疫约束，为以后做癌种定制组合提供思路；
3. **三线才写工具化和分层推荐**，避免主文被工程细节淹没；
4. 降级/备用分析写在方法，不写在目标，保持高刊气质。

---

## 7. 风险与限制（对IF>20的自觉声明）

1. 单细胞快照+软先验推断的因果方向仍为支持性而非最终证据，关键边需要体内验证确认；
2. LINCS 等药物资源对免疫联合药物的覆盖有限，因此分层推荐中非Tier A部分应视为假说；
3. 多癌种样本量不均衡已用加权和分癌种报告缓解，但极少数癌种仍只能做描述性；
4. 动物实验为算法达标后的阶段性任务，本方案只定义目标，不展开执行细节。
